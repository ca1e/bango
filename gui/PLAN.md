# 五子棋协议对弈 GUI · 开发计划

## 1. 目标与角色划分

浏览器 GUI 扮演 Gomocup 协议中的**管理器（Manager）**，AI 引擎是 **Brain**。
协议逻辑（protol.md）完全照搬，唯一差别：stdin/stdout 换成 TCP 连接 `127.0.0.1:9527`。

```
浏览器（管理器逻辑 + 全部游戏规则判定）
   │  HTTP(SSE 推送引擎输出行 / POST 下发命令行)
本地桥接服务（Node，零依赖：静态托管 + 字节搬运，不含任何协议语义）
   │  TCP
AI 引擎  127.0.0.1:9527   （pbrain-bango web --port 9527）
```

为什么需要桥接：浏览器无法直接建立 TCP 连接。桥接服务故意做得很"哑"，
协议状态机全部在前端实现，方便对照协议日志调试。

引擎侧三种接入方式（README 详述）：
1. `pbrain-bango web --port 9527`（本仓库引擎，原生 TCP）；
2. 任意标准 pbrain 引擎：`node tools/tcp-wrap.js --engine ./pbrain-xxx`（按连接拉起进程，stdio↔TCP）；
3. 无引擎联调：`node tools/mock-engine.js`（协议模拟引擎，含 MESSAGE 注入与 --dumb 模式）。

## 2. 协议实现要点（前端 = Manager）

- **会话生命周期 = 一条 TCP 连接**。开始对局/重新开始：若已连接先发 `END`
  （协议：引擎尽快退出/复位），断开，重连，`START n` → `OK` → `INFO…` →
  AI 先手则 `BEGIN`，玩家先手则等待玩家落子后 `TURN x,y`。
  与 bango web 模式的"串行会话、END/断开后复位"完全吻合。
- **行格式**：发送统一 `CR LF`；接收按 `CR / LF / CRLF` 切行（跨包 CRLF 短暂等待），
  空行忽略，超长行不崩溃。
- **应答等待**：先挂行监听再发命令（防应答早到丢失）；`MESSAGE/DEBUG` 剥离进日志；
  意外行记录后继续等待；等待超时（落子 90s、控制命令 10s）或连接断开即报错。
- **使用的命令**：`START` `INFO` `BEGIN` `TURN` `TAKEBACK` `BOARD` `END` `ABOUT`。
  可选命令失败回退：`TAKEBACK` 答 `UNKNOWN` 时回退为
  `END → 重连 → START → BOARD 重放`（field：引擎子=1，玩家子=2，按落子顺序），
  若引擎对 `DONE` 回了着法（计数型引擎判断轮次不同）则再 `TAKEBACK` 该子修正。
- **INFO**：`timeout_turn 10000`、`timeout_match 0`、`max_memory 0`、`game_type 0`、
  `rule`（无禁手=0，有禁手=4，与引擎 rules.go 的位值一致）；每次落子命令前发
  `INFO time_left 2147483647`（无限时哨兵值）。
- **轮次同步**：玩家制胜手不再发给引擎（对局已结束），每颗子记录 `sent` 标记，
  悔棋时只对引擎已知的子发 `TAKEBACK`。

## 3. 游戏规则（前端独立判定，不依赖引擎）

- 无禁手：连五及以上获胜。
- 有禁手（连珠，RIF 9.3）：黑方恰五胜；长连（≥6）犯规判白胜；白方连五及以上胜；
  禁手点（三三/四四/长连）标记红叉并**拒绝玩家点击**；AI 若落禁手点判白胜；
  黑方无合法点判白胜；满盘和棋。
- **禁手算法**：对候选点四方向枚举 4 步内的空点试填，
  填后过 (x,y) 连长恰为 5 → 一个"四"；恰为 4 且两端皆空（活四）→ 一个"三"；
  按"参与棋子集合"去重（活四两端算同一个四，保证"三可成活四"的定义自洽）。
  三的成活点本身不得是禁手点（RIF 递归校验，深度封顶 6 的近似，深层按不禁处理）。
  五连优先于一切禁手形状。该口径与引擎 rules.go 一致（引擎额外注明未做递归，
  只会把合法点误判为禁手、绝不会放过真禁手，故两者不会冲突）。

## 4. 悔棋语义

- 撤回到玩家上一次决策点：正常撤 2 手（AI + 玩家）；玩家最后一手是制胜手时撤 3 手
  （制胜手未发给引擎，引擎只需 TAKEBACK 前两手）。
- 对被撤且引擎已知的子**逆序**逐个 `TAKEBACK`，每次应答 `OK`。
- AI 思考中禁用悔棋；对局结束后仍可悔棋继续（清除胜负状态）。

## 5. UI 方案

视觉论点：深炭墨工作台上的一块暖木棋盘，木纹与棋子是唯一的高饱和元素，
朱红只出现在"最后一手 / 禁手 / 胜利连线"三种时刻。
参照 Lichess 的克制（深色铬、棋盘即色彩锚点）与 Piskvork 的功能全集。

- 布局：顶栏（标识 + 引擎连接状态/名称）→ 主区（棋盘 Canvas）+ 右栏
  （对局状态与控制 / 对局设置 / 落子记录 / 可折叠协议日志）。
- 设置：先手（玩家黑 / AI 黑）、禁手规则（无禁手[默认] / 有禁手连珠）、
  棋盘（20 路[默认] / 15 路）、引擎地址（默认 127.0.0.1:9527）。
  对局中锁定（结束后解锁），localStorage 记忆。
- 交互签名：落子 140ms 落定动画、悬停半透明预览、禁点红叉 + not-allowed 光标、
  胜利连线金环高亮。
- 胜负提示：全屏遮罩结果卡（大字结果 + 原因说明 + 再来一局 / 查看棋盘）。
- 协议日志：双向收发行着色展示，含 MESSAGE/DEBUG 与异常行，便于核对协议。

## 6. 测试

- `test/forbidden.test.mjs`：长连、恰五、三三、四四、活四不禁、四三不禁、
  眠三不计、递归假活三、白胜判定等用例。
- `tools/mock-engine.js`：全必选命令 + TAKEBACK/RESTART/ABOUT/PLAY + MESSAGE 注入。
- 浏览器端到端走查：玩家/AI 先手两向对局、胜负弹窗与连线高亮、悔棋、
  禁手标记与拒绝、重新开始、断线恢复。

## 7. 已定决策（默认值）

| 项 | 取值 | 理由 |
| --- | --- | --- |
| 默认先手 | 玩家（执黑） | 最常见的人机开局 |
| 默认禁手 | 无禁手 | 需求指定 |
| 默认棋盘 | 15 路（v2 更新，原 20） | 更通用的对弈尺寸；引擎拒绝时自动回退 20 |
| rule 位 | 0 / 4 | 与引擎 rules.go 及 Gomocup 惯例一致 |
| 悔棋粒度 | 撤一个完整回合 | 回到玩家决策点 |
| 胜负判定方 | 前端 | 管理器职责，引擎不参与判负 |
| 桥接端口 | 9528 | 避开引擎 9527 |
